# Services as Software

> "O software deixa de ser o produto. Vira a infraestrutura invisível que entrega resultados."

---

# Princípio Central

Durante os últimos 20 anos, empresas de software venderam ferramentas. A era da IA muda o produto.

Clientes não querem mais software. Querem trabalho concluído.

**Modelo antigo:** Software → Funcionário → Resultado

**Modelo novo:** IA + Software → Trabalho Concluído

O software vira a fábrica. O cliente só compra o que sai da fábrica.

---

# Modelos Mentais

## Venda Resultados, não Interfaces

Ninguém acorda querendo:

- CRM
- ERP
- Dashboard
- Agente de IA
- Workflow

As pessoas querem:

- Mais vendas
- Custos menores
- Contratação mais rápida
- Contabilidade melhor
- Mais pacientes
- Maior receita

Nunca venda a ferramenta. Venda o trabalho pronto.

---

## Software Vira Infraestrutura

O software continua existindo. A diferença é que o cliente raramente interage com ele.

```
Cliente → Solicita um resultado → Fábrica de IA executa → Resultado entregue
```

Internamente pode haver: agentes de IA, workflows, RAG, CRM, banco de dados, APIs, dashboards.

Externamente nada disso importa.

---

## Dispute o Orçamento Maior

Empresas gastam muito mais com mão de obra do que com software.

**Exemplo:** Software US$10k/ano vs Serviços Contábeis US$120k/ano.

Não dispute o budget de software. Dispute o budget operacional.

---

## Inteligência vs Julgamento

As melhores oportunidades de IA têm mais inteligência do que julgamento.

**Alta Inteligência:** código, revisão de documentos, criação de conteúdo, contabilidade, relatórios, suporte ao cliente.

**Alto Julgamento:** estratégia, liderança, negociação, visão, contratação de executivos.

Comece automatizando inteligência. Deixe o julgamento com humanos.

# Copilot vs Autopilot

(Framing Sequoia — [Services: The New Software](https://sequoiacap.com/article/services-the-new-software))

| | **Copilot** | **Autopilot** |
|---|-------------|---------------|
| Vende | A ferramenta | O trabalho / outcome |
| Cliente | O profissional (advogado, broker, contador) | Quem precisa do resultado (empresa, CFO) |
| Responsabilidade | O humano responde pelo output | Você entrega o resultado |
| Budget | Budget de software/tool | Budget de trabalho (mão de obra / outsourcing) |
| Exemplo | Harvey → escritórios de advocacia | Crosby → empresa que precisa de NDA, não o counsel |

Até pouco tempo, o caminho certo era copilot: modelo ainda fraco → coloque IA na mão do profissional. Em categorias com alto ratio de **inteligência**, o melhor ponto de partida já é autopilot.

**Regra:** quanto maior o ratio inteligência/julgamento no campo, mais cedo o autopilot vence.

---

# A Convergência

O julgamento de hoje vira a inteligência de amanhã.

À medida que o sistema acumula dados proprietários do que é “bom julgamento” no domínio, a fronteira se move. Copilots e autopilots convergem.

A posição inicial importa: quem começa como autopilot captura clientes e dados agora — e esses dados eventualmente permitem absorver também o julgamento.

---

# Wedge: Comece pelo que já é Terceirizado

Para cada US$1 gasto em software, cerca de US$6 vão para serviços.

O TAM do autopilot é **todo** o spend de labor da categoria (insourced + outsourced). Mas o lugar certo para começar é onde **já existe outsourcing**.

Se a tarefa já é terceirizada, três sinais:

1. A empresa aceitou que o trabalho pode ser feito fora
2. Existe linha de budget substituível (vendor swap, não reorg)
3. O buyer já compra **outcome**, não horas internas

**Playbook:**

```
Tarefa terceirizada + alta inteligência
        ↓
Nail distribuição (vendor swap)
        ↓
Composta dados do domínio
        ↓
Expande para trabalho interno + mais julgamento
```

A tarefa outsourced é o **wedge**. O trabalho insourced é o TAM de longo prazo.

Exemplo Sequoia: Crosby começou por NDAs — escopo claro, majoritariamente inteligência, já terceirizado para counsel externo. Budget existe, ROI imediato, fricção baixa.

---

# Mapa de Oportunidade (lente)

Plote cada vertical em dois eixos:

1. **Inteligência ↔ Julgamento**
2. **Outsourced ↔ Insourced**

Prioridade alta = alta inteligência + já outsourced (ou “trabalho abandonado” — long tail que ninguém cobre porque não é econômico com humanos).

| Vertical (ilustrativo) | Por que encaixa como wedge |
|------------------------|----------------------------|
| Contabilidade / close | Escassez estrutural de CPAs; close é regras complexas, mas regras |
| Revenue cycle (saúde) | Coding ICD-10 = tradução por regras; outsourcing maduro |
| Claims / brokerage | Processos padronizados; distribuição fragmentada |
| Legal transacional (NDA, filings) | Output verificável; já outsourced |
| IT managed services | Patch, monitor, triage em ambientes repetíveis — vender “seu IT roda”, não tool pro MSP |
| Procurement long-tail | Trabalho abandonado: leakage 2–5%; sem incumbent claro |
| Recruiting high-volume | Topo do funil = matching/outreach (inteligência); close = julgamento |

Mercados gigantes mas de **julgamento puro** (ex.: strategy consulting) são piores como wedge — a menos que você desagregue a camada de inteligência (data, benchmarking) da de julgamento (recomendação).

---

# Dilema do Copilot

Em 2025 muitos AI winners eram copilots. Virar autopilot exige cortar o próprio cliente da execução do trabalho — **innovator's dilemma**.

Essa é a abertura para autopilots pure-play: sem conflito de canibalizar quem paga pelo tool.

Se você vende o tool, corre contra o modelo de frontier. Se vende o trabalho, cada upgrade do modelo deixa seu serviço mais rápido, barato e difícil de competir.

# Flywheel

```
Serviço → Clientes reais → Problemas reais → Software interno → Custo menor → Margens melhores → Mais clientes → Mais dados → IA melhor
```

O software melhora continuamente o serviço. O serviço melhora continuamente o software.

# Perguntas para Fazer

Sempre que for construir um produto, pergunte:

> Qual trabalho o cliente está contratando alguém para fazer?

Em vez de:

> Qual software eu deveria construir?

Outra pergunta útil:

> Se a minha UI sumisse amanhã, o cliente ainda compraria o meu serviço?

Se sim, você provavelmente está construindo a coisa certa.

# Aplicando isso ao Gerenciei

**Posicionamento atual:** Clínica → Usa Gerenciei → Organiza operações

**Posicionamento futuro:** Paciente → Time de IA → Clínica cresce automaticamente

Em vez de vender CRM, agenda, WhatsApp, controle financeiro e relatórios, venda:

- Mais agendamentos
- Menos faltas
- Mais vendas de procedimentos
- Melhor retenção de pacientes
- Follow-up automatizado
- Respostas mais rápidas
- Cobranças automatizadas

---

# Clínica Autônoma

O Gerenciei deve se tornar um Sistema Operacional de IA — não um SaaS. O cliente compra uma operação autônoma.

### Agente de Recepção

- Responde WhatsApp e Instagram
- Qualifica pacientes
- Agenda consultas

### Agente de Vendas

- Faz follow-up de leads
- Envia propostas, negocia e fecha tratamentos

### Agente de Agenda

- Otimiza o calendário
- Confirma e remarca automaticamente

### Agente de Marketing

- Cria posts, roda campanhas, acompanha ROI e sugere promoções

### Agente Financeiro

- Envia cobranças, cobra pacientes, reconcilia pagamentos e prevê fluxo de caixa

### Agente de Relacionamento

- Follow-up pós-tratamento
- Coleta avaliações
- Reativa pacientes inativos
- Sugere novos procedimentos

### Agente Executivo

Toda manhã entrega: receita, ocupação, riscos, oportunidades e ações sugeridas.

Como ter um COO dentro da clínica.

Não construa software. Construa empresas autônomas.

# Princípios Lucas

- Nunca venda dashboards. Venda decisões.
- Nunca venda IA. Venda trabalho concluído.
- Nunca venda automação. Venda resultados.
- Complexidade interna deve criar simplicidade externa.
- Toda melhora nos modelos de IA deve reduzir o custo de entrega.
- Clientes raramente deveriam precisar abrir a plataforma.
- O melhor software desaparece.
- Todo negócio deveria perguntar: "Como seria esta empresa se funcionários de IA fizessem 90% do trabalho operacional?"
- Prefira autopilot (outcome) a copilot (tool) quando o ratio de inteligência for alto.
- Comece pelo trabalho já terceirizado — vendor swap, não reorg.
- Julgamento de hoje é inteligência de amanhã: posicione-se onde os dados compostos.
