# Meetings

## Objetivo

Usar reuniões só quando forem o melhor meio — com dono, objetivo, decisão e follow-through — e proteger foco do time do calendário predatório.

Resolve weeks de calls sem artefato, status theater e a cultura de “marca uma reunião” como reflexo.

---

## Filosofia

- Reunião é cara: pessoas × tempo × custo de troca de contexto.
- Default async. Reunião para conflito, decisão Tipo 1, relacionamento ou brainstorm com restrição.
- Sem objetivo e dono, é socialização disfarçada de trabalho.
- Status pode ser escrito. Decisão precisa de presença (às vezes).
- Quem convoca prepara. Quem não leu o pré-material observa, não opina.
- Toda reunião termina em donos, prazos e registro.
- Calendar vazio é sinal de sistema saudável, não de ociosidade.
- Menos participantes, mais verdade. Audiência larga vira performance.

## Framework

### 1. Gate: precisa ser reunião?

Só reúna se pelo menos um for verdadeiro:

1. Decisão com trade-offs que precisa debate ao vivo
2. Alinhamento emocional / conflito / sensível
3. Criação conjunta onde latência async dói
4. Cadência estratégica curta (ex.: weekly leadership)

Caso contrário: doc, Loom, ticket, Slack thread com deadline.

### 2. Design da reunião (antes)

| Elemento | Exigência |
|----------|-----------|
| Objetivo | 1 frase (“Decidir X” / “Desbloquear Y”) |
| Tipo | Decisão / workshop / 1:1 / review |
| Agenda | Tempos + tópicos |
| Pré-leitura | Enviada com ≥24h se possível |
| Participantes | Mínimo necessário + papéis |
| Dono | Quem facilita e fecha |

### 3. Tipos e duração alvo

| Tipo | Duração típica | Output |
|------|----------------|--------|
| 1:1 | 25–50 min | Notas + ações |
| Decision | 25–50 min | Decisão escrita |
| Weekly ops | 25–45 min | Bloqueios + prioridades |
| Review/demo | 30–60 min | Feedback + next |
| Brainstorm | 40–90 min | Opções ranqueadas |
| All-hands | 30–45 min | Narrativa + Q&A |

Se sempre estoura, a agenda está inflada ou falta pré-trabalho.

### 4. Durante

```
Objetivo no minuto 0
        ↓
Pré-leitura assume-se lida
        ↓
Debate por critérios
        ↓
Decisão / next steps
        ↓
Registro no doc
```

Facilitador corta digressão com: “isso é para outro fórum — capturar e seguir”.

### 5. Depois (obrigatório)

Em ≤24h:

- Decisões
- Actions: dono + prazo
- Link no lugar canônico (não só chat)

Sem isso, a reunião não aconteceu — só o tempo foi gasto.

### 6. Higiene de calendário

- Blocos de foco sagrados
- No-meeting half-days se o trabalho for deep work
- Recurrences com review trimestral (mate zumbis)
- Decline educado sem objective/agenda

### 7. Template rápido de agenda

1. Contexto (2–5 min)
2. Discussão (bulk)
3. Decisão
4. Actions
5. Parque de ideias (não resolver agora)

## Aplicações

### SaaS

Weekly growth/product: métricas + 1–2 decisões. Status em dashboard async.

### IA

Review de evals/incidentes: curta, com dados na mesa. Evite reunião de “feeling do modelo”.

### Empresas B2B

Deal review: só deals que precisam de ajuda. Pipeline dump é relatório.

### Produtos Digitais

Critique sessions com artefato pré-enviado. Sem drive-by opinions.

### Startups

Fundador: audite seu calendário semanalmente. Se >50% em reuniões reativas, sistema quebrou.

## Erros Comuns

| Erro | Efeito | Correção |
|------|--------|----------|
| Reunião sem agenda | Drift | Gate + template |
| Elenco inchado | Teatro | Mínimo viável |
| Status oral | Tempo morto | Async + dashboard |
| Sem decisão/registro | Retrabalho | Close obrigatório |
| Recurring zumbi | Burn coletivo | Review trimestral |
| Multitarefa | Falsa presença | Norma de atenção |

---

## Checklist

- [ ] Objetivo cabe em uma frase
- [ ] Async foi considerado e rejeitado com motivo
- [ ] Agenda e pré-leitura enviadas
- [ ] Participantes mínimos definidos
- [ ] Dono/facilitador claro
- [ ] Começa e termina no horário
- [ ] Decisão ou aprendizado explícito
- [ ] Actions com dono e prazo
- [ ] Registro no lugar certo
- [ ] Recurring ainda justifica existência
