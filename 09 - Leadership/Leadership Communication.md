# Leadership Communication

## Objetivo

Comunicar direção, contexto e decisões com clareza e cadência — para o time executar alinhado sem rumores, retrabalho ou dependência de “estar na sala certa”.

Resolve rádio-irmão, all-hands theater e líderes que falam muito e informam pouco.

---

## Filosofia

- Clareza é gentileza. Ambiguidade força o time a adivinhar.
- Comunica-se para alinhamento e ação — não para performance pessoal.
- Contexto > ordem. Adultos executam melhor quando entendem o porquê.
- Repetição não é insulto: mensagem estratégica precisa de múltiplos canais e vezes.
- Escrita escala. Reunião não substitui doc canônico.
- Transparência seletiva e honesta > otimismo falso. Confiança é o ativo.
- Tom do líder define o clima. Pânico e cinismo são contagiosos.
- Ouvir é metade da comunicação de liderança — senão você transmite no vazio.

## Framework

### 1. Cascata de mensagem (Message Architecture)

Para qualquer mudança material, escreva:

1. **O quê** mudou / foi decidido
2. **Porquê** (negócio, evidência)
3. **O que não muda**
4. **O que esperamos de cada área**
5. **Como mediremos**
6. **Onde perguntar / discordar**
7. **Próximo update**

Sem isso: cada manager inventa uma versão.

### 2. Canais e usos

| Canal | Use para | Não use para |
|-------|----------|--------------|
| Doc / Notion / memo | Decisão, estratégia, política | Chat efêmero |
| Async (Slack/Loom) | Updates, contexto curto | Tipo 1 sensível só ali |
| All-hands | Narrativa + Q&A | Status detalhado |
| 1:1 | Desenvolvimento, temas locais | Único lugar da estratégia |
| Meeting de decisão | Trade-offs ao vivo | Substitui registro |

Regra: se importa em 30 dias, está escrito no lugar canônico.

### 3. Cadência mínima de liderança

```
Semanal: prioridades + riscos (curto)
        ↓
Mensal: progresso vs. plano + learnings
        ↓
Trimestral: direção, aposta, headcount/capacity
```

Consistência cria segurança. Surpresão contínua cria fadiga.

### 4. Framework de difficult messages

Mau resultado, layoff, pivot, corte de projeto:

1. Direto no primeiro parágrafo
2. Contexto factual
3. Impacto humano reconhecido
4. Próximos passos concretos
5. Espaço para pergunta
6. Follow-up datado

Não enterre a lead. Não prometa o que não controla.

### 5. Listening system

- Office hours / AMA
- Sintese de dúvidas recorrentes → FAQ vivo
- Skip-levels periódicos
- Sinais de rumor: trate com fato público rápido

### 6. Qualidade da mensagem

Checklist de edição:

- Uma ideia central?
- Jargão cortável?
- Ação pedida está óbvia?
- Ambíguo sob pressão?
- Tempo de leitura < 3–5 min para ops updates?

## Aplicações

### SaaS

Comunique mudanças de pricing/packaging com script único para Sales+CS. Evite versões conflitantes.

### IA

Comunique limitações e políticas de uso internamente com a mesma honestidade que ao mercado.

### Empresas B2B

Narrative de roadmap para cliente ≠ commitment casual de AE. Alinhe porta-vozes.

### Produtos Digitais

Changelog interno + tese: o time sabe por que shipamos X e não Y.

### Startups

Fundador: 1 memo curto > 5 reuniões nebulosas. Escreva a estratégia.

## Erros Comuns

| Erro | Efeito | Correção |
|------|--------|----------|
| Só oral | Distortion | Memo canônico |
| Otimismo falso | Quebra de confiança | Transparência factual |
| Oversharing ansioso | Pânico | Cadência + filtro |
| Mensagem uma vez | Drift | Repetir em canais |
| Sem listening | Surdez estratégica | AMA + síntese |
| Tom inconsistente | Confusão emocional | Princípios de comunicação |

## Checklist

- [ ] Message architecture completa (quê/porquê/ações)
- [ ] Canal certo para o tipo de conteúdo
- [ ] Registro canônico atualizado
- [ ] Managers preparados para cascata
- [ ] Q&A path existe
- [ ] Cadência de updates está no calendário
- [ ] Mensagens difíceis são diretas e humanas
- [ ] Rumores tratados com fato rápido
- [ ] Escuta periódica acontece
- [ ] Ação pedida está explícita

## Modelo Mental

```
Decisão / mudança
        ↓
Mensagem escrita (quê + porquê + ações)
        ↓
Canal certo + cascata
        ↓
Repetição e Q&A
        ↓
Escuta e ajuste
        ↓
Alinhamento executável
```
