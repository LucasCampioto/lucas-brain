# AI Business Opportunities

## Objetivo

Identificar, priorizar e validar oportunidades de negócio com IA onde há willingness-to-pay, dados acessíveis e vantagem defensável — não ideias de “wrapper de API”.

Resolve listas infinitas de “casos de uso” sem ICP, sem unit economics e sem caminho para moat.

---

## Filosofia

- Oportunidade = job caro + frequência + dados + distribuição, não modelo novo.
- Dinheiro está em workflows de orçamento (venda, suporte, risco, ops, compliance, criação).
- Genérico atrai curiosos; específico no ofício atrai contratos.
- Wedge estreito que vira sistema de record > assistente horizontal.
- Custo variável (tokens/tools) entra no pricing desde o slide 1.
- Timing: o que ficou barato/possível agora que não era há 18 meses?
- Validação é conversa com comprador e piloto mensurável, não demo viral.
- Build vs partner vs feature: escolha pelo acesso ao workflow e aos dados.

## Framework

### 1. Caça de oportunidades (lentes)

| Lente | Pergunta |
|-------|----------|
| Budget existing | De onde já sai dinheiro (agências, BPO, software, headcount)? |
| Pain frequency | Quão vezes por semana o job dói? |
| Data exhaust | Que artefactos já existem (tickets, PDFs, calls, CRM)? |
| Latency tolerance | Minutos ok ou precisa ms? |
| Error budget | Errar custa e-mail ou processo judicial? |
| Distribution | Quem já vende para esse ICP? |

### 2. Scorecard de priorização

Pontue 1–5:

1. Intensidade do problema  
2. Acesso a comprador  
3. Dados / integração viável  
4. Willingness-to-pay sinalizado  
5. Defensabilidade em 12–24 meses  
6. Custo de servir aceitável  
7. Complexidade regulatória (invertida)

Só avance top scores. O resto é backlog, não pivô emocional.

### 3. Tipos de aposta

| Tipo | Exemplo de wedge |
|------|------------------|
| Copilot no workflow | Assist no tool que já é system of record |
| Automation outcome | “Processamos X com SLA” |
| Data network | Quanto mais uso, melhor o modelo/regras do domínio |
| Vertical suite | Um ofício, vários jobs encadeados |
| Infra/tooling | Eval, observability, orchestration — se ICP de builders for real |

### 4. Validação em semanas

```
Hipótese de job + ICP
        ↓
10 conversas com compradores
        ↓
Artefacto de valor (não slide)
        ↓
Piloto pago ou carta de intent
        ↓
Métrica de outcome acordada
        ↓
Decisão: double down / pivot / kill
```

Sem pagamento ou intenção forte, não é oportunidade — é interesse educado.

### 5. Unit economics rápidos

- Custo variável por outcome (tokens + tools + humanos de review)
- Preço ancorado em valor (horas, % erro, revenue lift)
- Margem alvo após review humano no v1
- Quando o custo do modelo cair, o que impede preço ir a zero? (dados, workflow, distribuição)

### 6. Moat realista

Ordem típica de força:

```
Acesso ao workflow + switching cost
        ↓
Dados proprietários + feedback loop
        ↓
Eval/qualidade no domínio
        ↓
Distribuição / brand no ofício
        ↓
Modelo proprietário (raro no início)
```

API pública + UI bonita ≠ moat.

### 7. Red flags

- “Todo mundo é cliente”
- Zero integração com sistema onde o trabalho mora
- Dependência total de um modelo frontier sem camada sua
- Compliance impossível no ICP (e você ignora)
- Demo metrica ≠ métrica do comprador

## Aplicações

### SaaS

Empacotar IA como módulo pago no produto existente: mesmo ICP, novo outcome, upsell.

### IA

Empresa nativa de IA: escolha um vertical job e domine o outcome end-to-end.

### Empresas B2B

Oportunidades internas (margem) vs produto (receita). Não misture portfolio sem dono.

### Produtos Digitais

IA que aumenta criação/conversão com métrica de negócio (CPC, retention, pace de publish).

### Startups

Uma oportunidade, um ICP, um piloto. Resista à plataforma horizontal no seed.

## Erros Comuns

| Erro | Efeito | Correção |
|------|--------|----------|
| Ideia por hype de modelo | Mercado indiferente | Partir do job/budget |
| ICP amplo demais | Mensagem morta | Wedge vertical |
| Ignorar COGS de IA | Margem negativa | Modelar custo/outcome |
| Validar só com amigos | Falso sinal | Compradores reais |
| Wrapper sem dados | Commoditização | Workflow + dados |
| Piloto eterno grátis | Sem aprendizado de P&L | Piloto pago |
| Moat = “nosso prompt” | Cópia em semanas | Switching + data loop |

---

## Checklist

- [ ] Job e ICP enunciados em uma frase
- [ ] Budget atual do problema identificado
- [ ] Scorecard preenchido vs outras ideias
- [ ] Caminho de dados/integração realista
- [ ] Hipótese de preço e COGS
- [ ] 10 conversas com compradores feitas
- [ ] Artefacto/piloto com métrica de outcome
- [ ] Sinal de pagamento ou intent documentado
- [ ] Tese de moat em 12–24 meses
- [ ] Critério explícito de kill/pivot
