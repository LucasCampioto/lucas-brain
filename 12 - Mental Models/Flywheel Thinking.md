# Flywheel Thinking

## Objetivo

Projetar e operar um ciclo virtuoso em que cada volta torna a próxima mais fácil e mais valiosa — concentrando energia no volante, não em empurrões aleatórios.

Resolve growth “a jato” que some quando a campanha para, porque não há mecanismo cumulativo.

---

## Filosofia

- Flywheel ≠ buzzword: precisa de etapas e acúmulo real.
- Empurrões constantes e alinhados batem hero push ocasional.
- Cada etapa deve tornar a seguinte mais barata ou melhor.
- Friction em qualquer estágio mata o momento.
- Medir velocidade do volante (inputs → outcomes → reforço).
- Não declare flywheel antes de provar o reforço com dados.
- Um flywheel bem escolhido > cinco “estratégias” paralelas.
- Paciência e consistência são parte do design.

---

## Framework

### 1. Anatomia

```
Etapa A melhora B
        ↓
B melhora C
        ↓
C melhora A (reforço)
        ↓
Acúmulo (dados, brand, densidade, liquidez)
```

Se não houver retorno a A, não é flywheel — é funnel.

### 2. Teste de validação

1. O que acumula a cada volta? (asset)
2. O custo por volta cai ou o valor sobe?
3. Se parar o empurrão externo, o ciclo ainda gira um pouco?
4. Qual etapa é o gargalo atual?

### 3. Exemplos de negócios

| Tipo | Loop |
|------|------|
| Conteúdo | Conteúdo → tráfego → leads → receita → mais conteúdo |
| Marketplace | Demanda → oferta → liquidez → conversão → mais demanda |
| SaaS PLG | Uso → valor → seats → dados → melhor produto |
| IA | Uso → dados → modelo → retenção → mais uso |

### 4. Operação

- Escolha **um** flywheel primário no estágio
- Identifique a alavanca de maior torque agora
- Remova atrito (UX, pricing, onboarding, tempo de sync oferta/demanda)
- Empurre com cadência (weekly) na alavanca
- Revise o gargalo mensalmente

### 5. Anti-flywheel

- Canais pagos que não melhoram produto/brand
- Features espalhadas sem acumular vantagem
- Descontos que ensinam a esperar promoção

---

## Aplicações

### SaaS

PLG: time-to-value → habit → invite → expansion. Instrumente cada dente do volante.

### IA

Só chame de data flywheel se o dado for proprietário, legal e melhorar o produto de forma perceptível.

### Empresas B2B

Referências e cases: win → success story → pipeline mais fácil → mais wins em ICP.

### Produtos Digitais

Creator/community loops: cuidado com loops que dependem de paid forever.

### Startups

Desenhe o flywheel em 4–6 caixas. Se não cabe num napkin, ainda não está claro.

## Erros Comuns

| Erro | Efeito | Correção |
|------|--------|----------|
| Funnel disfarçado | Sem acúmulo | Teste do reforço |
| Vários volantes | Energia diluída | Um primário |
| Ignorar gargalo | Torque zero | Focar a etapa lenta |
| Narrative sem dados | Autoilusão | Métricas por etapa |
| Empurrão só em lançamento | Para o volante | Cadência |
| Atrito não medido | Fricção oculta | Drop-off por stage |

## Checklist

- [ ] Etapas desenhadas em ciclo
- [ ] Asset que acumula nomeado
- [ ] Métricas por etapa
- [ ] Gargalo atual identificado
- [ ] Alavanca de torque definida
- [ ] Cadência de empurrão
- [ ] Distinto de funnel puro
- [ ] Um flywheel primário
- [ ] Atritos listados com donos
- [ ] Revisão mensal do gargalo
- [ ] Ligado a Quarter Planning
- [ ] Evidência de reforço (não só slide)

