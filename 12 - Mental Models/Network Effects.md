# Network Effects

## Objetivo

Entender quando o valor do produto aumenta com mais usuários/participantes — e projetar (ou não apostar em) defesas baseadas nessa dinâmica.

Resolve pitch de “network effects” usado como magia, sem especificar quem se beneficia e onde a densidade importa.

---

## Filosofia

- Network effect é empírico: valor sobe com N de forma observável.
- Densidade local costuma importar mais que N global.
- Nem todo negócio viral tem network effect.
- Efeitos de marca, escala e dados ≠ network effects (podem coexistir).
- Multi-sided markets têm cold start e chicken-egg.
- Same-side e cross-side effects pedem estratégias diferentes.
- Defensibilidade real exige efeito forte + switching costs saudáveis.
- Falsos network effects levam a burn em aquisição sem moat.

## Framework

### 1. Classificação rápida

| Tipo | Ideia | Exemplo |
|------|-------|---------|
| Direto (same-side) | Mais users → mais valor entre iguais | Chat, social |
| Crowss-side | Mais lado A ajuda lado B | Marketplace, ads |
| Dados | Mais uso → melhor modelo/UX | IA com feedback loop |
| Plataforma | Ecossistema de integrações | APIs, plugins |

### 2. Teste ácido

1. Se amanhã metade dos usuários sumir, o valor para o remanescente cai de forma material?
2. O valor é local (grafo, cidade, ICP) ou global?
3. Há cold start? Como se resolve uma fatia pequena?
4. O efeito é copiável com dinheiro puro?

### 3. Cold start playbook

```
Escolher nicho denso
        ↓
Suprir o lado escasso manualmente
        ↓
Chegar a liquidez mínima
        ↓
Expandir geometria (adjacências)
```

### 4. Métricas

- Liquidez / match rate
- Retenção vs tamanho do grafo local
- Densidade (conexões por usuário)
- Viral coefficient (ajuda distribuição, não prova NE)
- Willingness to pay conforme rede cresce

### 5. Anti-padrão de pitch

Evite chamar de network effect:

- Economias de escala puras
- Brand awareness
- “Temos um Discord”

---

## Aplicações

### SaaS

Integrações e multiplayer workflows podem criar platform effects; collaboration real é same-side.

### IA

Data network effects só com dados proprietários + melhoria mensurável + barreira de acesso ao dado.

### Empresas B2B

Redes de compradores/fornecedores, marketplaces verticais: foque liquidez por categoria/geo.

### Produtos Digitais

Social/graph: priorize densidade em comunidades pequenas antes de scale pago.

### Startups

Se não há NE claro, construa valor single-player excelente. NE prematuro queima foco.

## Erros Comuns

| Erro | Efeito | Correção |
|------|--------|----------|
| Label marketing | Estratégia errada | Teste ácido |
| Scale global cedo | Sem liquidez | Nicho denso |
| Pagar os dois lados forever | Sem unit economics | Path to organic |
| Ignorar same vs cross | Ação invertida | Classificar efeito |
| Confundir viral com NE | CAC ilusão | Valor com N |
| Lock-in tóxico | Churn de brand | Switching costs justos |

## Checklist

- [ ] Tipo de efeito nomeado
- [ ] Teste ácido passou (ou honestamente não)
- [ ] Unidade de densidade definida
- [ ] Estratégia de cold start
- [ ] Métricas de liquidez/retenção local
- [ ] Single-player value existe
- [ ] Unit economics sustentáveis
- [ ] Não confundido com brand/scale
- [ ] Expansão por adjacência planejada
- [ ] Defensibilidade realista
- [ ] Ligado a flywheel/data loop se houver
- [ ] Pitch interno honesto

## Modelo Mental

```
Mais N (na densidade certa)
        ↓
Mais valor por usuário
        ↓
Mais retenção / atração
        ↓
Mais densidade
        ↓
Moat (se efeito for real)
```
