# Systems Thinking

## Objetivo

Ver o negócio como sistema de partes interdependentes — estoques, fluxos, feedbacks e atrasos — para intervir nas alavancas certas em vez de apagar sintomas locais.

Resolve otimizações locais que pioram o todo (vendas vs CS, feature vs confiabilidade, crescimento vs margem).

---

## Filosofia

- O comportamento emerge da estrutura, não só das intenções das pessoas.
- Empurrar um nó move outros — mapeie antes de “acelerar”.
- Estoques (caixa, confiança, dívida técnica, pipeline) importam tanto quanto fluxos.
- Atrasos enganam gestores ansiosos.
- Alavancas altas são raras; a maioria das ações é baixo torque.
- Culpar indivíduos esconde desenho de sistema ruim.
- Clareza de propósito do sistema evita métricas conflitantes.
- Desenhe o sistema que você gostaria que o time habitasse.

## Framework

### 1. Elementos

| Elemento | Pergunta |
|----------|----------|
| Propósito | O sistema otimiza o quê de verdade? |
| Partes | Times, ferramentas, políticas |
| Fluxos | Leads, trabalho, dinheiro, informação |
| Estoques | Backlog, runway, trust, qualidade |
| Feedbacks | O que reforça/equilibra |
| Atrasos | Onde o sinal chega tarde |
| Fronteira | O que está in/out da análise |

### 2. Diagrama causal mínimo

```
Meta / pressão
        ↓
Comportamento local
        ↓
Efeito em estoque/fluxo
        ↓
Feedback (+/−) com delay
        ↓
Novo comportamento
```

### 3. Alavancas (ordem típica de potência)

1. Propósito / paradigmas
2. Regras e incentivos
3. Estrutura de informação (quem vê o quê)
4. Loops de feedback
5. Parâmetros (metas numéricas)
6. Sintomas (apagar fogo)

Gaste energia no alto da lista quando possível.

### 4. Protocolo de intervenção

1. Sintoma observado
2. Mapa de 5–9 nós
3. Hipótese de estrutura
4. Intervir em alavanca alta / barata
5. Monitorar efeitos de 2ª ordem
6. Ajustar

### 5. Anti-sintoma

| Sintoma | Intervenção fraca | Olhe o sistema |
|---------|-------------------|----------------|
| Churn alto | Desconto | Valor / onboarding / ICP |
| Cycle longo | Pressure sellers | Handoffs / pricing / ICP |
| Bugs | Heroismo | Processo de qualidade / WIP |
| Burnout | Happy hour | Carga, DRI, escopo |

## Aplicações

### SaaS

Funil + produto + CS como um sistema de retenção e NRR; não otimize SQL se ativação quebra.

### IA

Dados → modelo → UX → uso → dados: intervenha onde o ciclo emperra (avalição, custo, workflow).

### Empresas B2B

Marketing–Sales–CS–Produto: contratos de handoff e metas alinhadas ao mesmo propósito.

### Produtos Digitais

Growth loops vs engajamento tóxico: estrutura de incentivo do algoritmo/conteúdo.

### Startups

Comece mapeando 1 sistema crítico (ex.: do lead ao valor). Não modele a galáxia.

## Erros Comuns

| Erro | Efeito | Correção |
|------|--------|----------|
| Otimização local | Todo piora | Métrica de sistema |
| Só parâmetros | Pouco torque | Subir alavancas |
| Mapa infinito | Paralisia | 5–9 nós |
| Culpar pessoas | Estrutura intacta | Redesign incentivos |
| Ignorar delay | Overcorrection | Canários |
| Sem propósito claro | Metas em guerra | Explicitar objetivo |

## Checklist

- [ ] Propósito do sistema escrito
- [ ] Partes e fronteira definidas
- [ ] Estoques e fluxos nomeados
- [ ] Feedbacks e delays anotados
- [ ] Sintoma ≠ causa assumida
- [ ] Alavanca escolhida com consciência
- [ ] Efeitos de 2ª ordem considerados
- [ ] Métricas alinhadas ao propósito
- [ ] Handoffs / incentivos revisados
- [ ] Mapa cabe em uma página
- [ ] Review após intervenção
- [ ] Ligado a Feedback Loops / Decision Trees
