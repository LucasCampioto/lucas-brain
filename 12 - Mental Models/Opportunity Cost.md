# Opportunity Cost

## Objetivo

Toda escolha consome a melhor alternativa não tomada — tornar esse custo explícito para evitar “sim” baratos que destroem o foco.

Resolve decisões avaliadas só pelo benefício da opção favorita, sem perguntar “em vez de quê?”.

---

## Filosofia

- Recursos (tempo, atenção, caixa, runway) são finitos.
- O custo real de X é o melhor Y abandonado.
- “Podemos fazer os dois” costuma significar “os dois mal feitos”.
- Custo de oportunidade cresce com o valor do seu tempo e do capital.
- Manter opção aberta também custa (atenção, complexidade).
- Sunk cost ≠ opportunity cost — não confunda.
- Decisões boas parecem “caras” no curto e baratas no longo.
- Explicitar o trade-off reduz arrependimento político.

---

## Framework

### 1. Pergunta canônica

Antes de comprometer:

> Se fizermos A, qual é a melhor coisa que deixamos de fazer nos próximos 30/90 dias?

Escreva a alternativa concreta — não “outras coisas”.

### 2. Matriz rápida

| Opção | Benefício esperado | Recurso consumido | Melhor alternativa sacrificada | Vale? |
|-------|--------------------|-------------------|--------------------------------|-------|
| A | | | | |
| B | | | | |
| Nada | | | | |

### 3. Tipos de custo

1. **Tempo de calendário** (latência até o outcome)
2. **Atenção de líderes** (o recurso mais raro)
3. **Capacidade de engenharia/CS**
4. **Opção estratégica** (caminhos fechados)
5. **Complexidade** (custo permanente no sistema)

### 4. Protocolo de “sim”

```
Pedido / ideia atraente
        ↓
Qual recurso absoluto consome?
        ↓
Qual aposta do Q ela desloca?
        ↓
Se desloca a #1 sem beat claro → não
        ↓
Se empatado → experimento barato ou adiar
```

### 5. Preço do “talvez”

Backlog infinito tem custo de oportunidade cognitivo. WIP limit e “não faremos” do Quarter Planning são defesa.

## Aplicações

### SaaS

Custom para um logo: ganho de deal vs atraso do produto que serve 100 contas.

### IA

Mais um modelo/fine-tune vs melhorar evals e UX do use case que já paga.

### Empresas B2B

RFP fora de ICP: receita potencial vs diluição de time e brand.

### Produtos Digitais

Feature requests barulhentas vs hipoteses ligadas a retention.

### Startups

Fundraise theater, side projects e “parcerias” — meça contra aprender com clientes e shipar o core.

## Erros Comuns

| Erro | Efeito | Correção |
|------|--------|----------|
| Avaliar só benefício | Overcommit | Forçar alternativa sacrificada |
| Ignorar atenção de líderes | Gargalo oculto | Contar horas de DRI |
| Confundir com sunk cost | Persistência tóxica | Olhe frente, não atrás |
| “É só uma feature” | Slippage | Somar custo de complexidade |
| Não escrever o não | Reabertura eterna | Lista “não faremos” |
| Otimizar centavos | Perder dólares | Escala do recurso |

---

## Checklist

- [ ] Alternativa sacrificada nomeada
- [ ] Recurso escasso identificado
- [ ] Impacto nas apostas do trimestre
- [ ] Custo de complexidade considerado
- [ ] Opção “nada / adiar” na mesa
- [ ] Atenção de líderes contabilizada
- [ ] Decisão registrada (ADR leve)
- [ ] Critério de revisitação
- [ ] Sem misturar sunk cost
- [ ] Time alinhado no trade-off
- [ ] WIP não explode
- [ ] Revisão pós-fato do custo real
