# Execution Framework

## Objetivo

Converter intenção estratégica em entrega contínua: prioridade clara, donos, ritmo de ship/learn e fechamento — sem confundir movimento com progresso.

Resolve roadmaps bonitos, semanas ocupadas e pouca mudança nas métricas que importam.

---

## Filosofia

- Execução é o único juiz da estratégia.
- Foque: poucas prioridades reais. Se tudo é P0, nada é.
- Done instrumentado > almost done perfeito.
- Dono único por iniciativa. Comitês não executam.
- Ritmo sustentável vence sprint heroico seguido de hangover.
- Aprendizado faz parte da execução: medir, interpretar, ajustar.
- Bloqueios sobem cedo com proposta — não com drama tardio.
- Sistema de execução deve ser leve o bastante para o estágio.

---

## Framework

### 1. Cascata de execução

```
Aposta do trimestre (1–3)
        ↓
Iniciativas com DRI
        ↓
Work breakdown semanal
        ↓
Ship / learn loop
        ↓
Weekly Review
        ↓
Ajuste ou kill
```

### 2. Carta da iniciativa (1 página)

1. Outcome (métrica / comportamento)
2. Hipótese
3. Escopo in/out
4. DRI e colaboradores
5. Milestones datados
6. Dependências
7. Critério de sucesso / falha
8. Próximo check

Sem carta: é hobby organizacional.

### 3. Priorização semanal

Toda semana, time/líder responde:

1. Qual a coisa #1 que move o outcome?
2. O que vamos terminar (não só começar)?
3. O que bloqueia e quem desarma?
4. O que vamos dizer não esta semana?

### 4. Loop de ship

| Etapa | Pergunta |
|-------|----------|
| Build | Estamos no caminho crítico? |
| Ship | Foi para produção / mercado? |
| Instrument | Dá para medir? |
| Learn | O que os dados/conversas dizem? |
| Decide | Dobrar / iterar / parar? |

### 5. Gestão de WIP

- Limite trabalho em progresso
- Prefira terminar a iniciar
- Visualize board simples (só se usado)
- Cerimonias curtas > status longos

### 6. Fechamento

Iniciativa fecha quando:

- Critério de sucesso/falha avaliado
- Learnings escritos
- SOP/playbook atualizado se repetível
- Próxima aposta explícita (ou stop)

Não deixe zumbis eternamente “at 90%”.

### 7. Papel do líder na execução

- Remover bloqueios
- Manter foco (proteger de novos P0s)
- Cobrar evidência, não teatro
- Recalibrar capacidade vs. ambição

## Aplicações

### SaaS

Execução ligada a north-star + input metrics (ativação, retention). Feature sem hipótese = WIP sujo.

### IA

Execução inclui gate de qualidade. Ship de modelo/prompt com eval — não só merge.

### Empresas B2B

Iniciativas de revenue com mutual plan e forecast hygiene. Execução ≠ activity logging.

### Produtos Digitais

Release train + experimentos. Cadência previsível de aprendizado.

### Startups

Uma aposta principal por vez no early. Parallelismo excessivo mata velocidade real.

## Erros Comuns

| Erro | Efeito | Correção |
|------|--------|----------|
| Muitas prioridades | Mediocridade | 1–3 Q bets |
| Sem DRI | Drift | Carta + dono |
| Começar > terminar | WIP infinito | WIP limit |
| Sem métrica | Opinião | Instrumentação |
| Kill evitado | Zumbi | Fail criteria |
| Status theater | Falso progresso | Artefatos + números |

---

## Checklist

- [ ] Apostas do trimestre claras
- [ ] Cada iniciativa tem carta e DRI
- [ ] Prioridade #1 da semana explícita
- [ ] WIP sob controle
- [ ] Ship com instrumentação
- [ ] Weekly Review com decisões
- [ ] Bloqueios com owner
- [ ] Learnings registrados
- [ ] Zumbis killados ou reescopados
- [ ] Líder protege foco
