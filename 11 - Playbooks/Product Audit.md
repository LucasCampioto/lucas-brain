# Product Audit

## Objetivo

Auditar produto como sistema de valor — ICP fit, job core, ativação, retenção, roadmap e qualidade — para decidir o que construir, o que matar e o que simplificar.

Resolve feature factories, roadmap político e produtos “ricos” que ninguém ativa.

---

## Filosofia

- Produto bom reduz tempo até o valor e aumenta frequência/intensidade do uso que importa.
- Feature ≠ valor. Valor é outcome no workflow do cliente.
- Auditoria começa em uso e retenção no ICP, não na lista de pedidos do maior cliente.
- Roadmap sem tese é backlog de ansiedade.
- Complexidade acumula como dívida; audit deve matar, não só adicionar.
- PMF é contínuo: o produto drift-a; o mercado também.
- Qualidade (reliability, UX, suporte) é produto — não afterthought.
- Escute o comportamento (dados) e a voz (entrevistas). Um sozinho mente.

## Framework

### 1. Camadas do produto

```
ICP e job-to-be-done
        ↓
Promessa do produto
        ↓
Core loop / wedge
        ↓
Ativação (path to aha)
        ↓
Hábitos e retenção
        ↓
Expansão de valor (features adjacentes)
        ↓
Qualidade e operações
```

### 2. Sequência da auditoria

1. **ICP atual vs quem usa de verdade**
2. **Job core**: o que o produto deve fazer no day 1
3. **Funil de ativação** e time-to-value
4. **Retention cohorts** + frequency of core action
5. **Feature adoption**: o que é usado vs shelfware
6. **Qualidade**: bugs críticos, uptime, support themes
7. **Roadmap vs tese**: % alinhado ao wedge
8. **Kill/simplify list** + 3 apostas de produto

### 3. Scorecard de produto

| Dimensão | Pergunta | Sinal de alerta |
|----------|----------|-----------------|
| Fit | ICP retém? | Uso fora do ICP |
| Clareza | Usuário entende o job? | Setup abandonado |
| Aha | % atinge valor? | < limiar definido |
| Habit | Frequência core ok? | One-shot usage |
| Amplitude | Features orfãs? | Adoption < 10% |
| Qualidade | Confiável? | Churn por bugs |
| Escopo | Roadmap focado? | 20 frentes |
| Feedback | Loop fechado? | Pedidos sem síntese |

### 4. Matriz de features

Classifique features ativas:

| Tipo | Ação |
|------|------|
| Core (define o produto) | Dobrar qualidade/UX |
| Amplifiers (aumentam retenção) | Investir se adoção existe |
| Table stakes | Manter mínimo |
| Distractions | Simplificar / matar |
| Bets | Tempo-box + critério |

### 5. Entregável

1. Diagnóstico (1 parágrafo)
2. Redefinição (ou reafirmação) do wedge
3. Top problemas de ativação/retenção
4. Kill/simplify list
5. 3 bets de produto com métricas
6. O que o roadmap para de atender

## Aplicações

### SaaS

Audite permissions, empty states e integrações como parte do path to aha — não só a feature “sexy”.

### IA

Qualidade do output, avaliação, e fallback humano são produto. Audite hallucination/failure modes no job real.

### Empresas B2B

Separe pedidos enterprise (governance) de core workflow. Não deixe um logo escrever o roadmap inteiro.

### Produtos Digitais

First session e performance são produto. Audite friction e “momento wow” nas primeiras ações.

### Startups

Audit = disciplina contra overbuild. Corte escopo até o job #1 brilhar.

## Erros Comuns

| Erro | Efeito | Correção |
|------|--------|----------|
| Roadmap por grito do cliente | Frankenstein | Wedge + ICP |
| Nunca matar feature | Complexidade | Kill list |
| Ignorar ativação | Aquisição inútil | Path to aha |
| Dados sem entrevista | Falsa precisão | 5–10 calls |
| Qualidade “depois” | Churn silencioso | Budget de fix |
| Competitor clone | Commodity | Job distinto |

---

## Checklist

- [ ] ICP vs usuários reais comparado
- [ ] Job core e aha reescritos
- [ ] Ativação e time-to-value medidos
- [ ] Cohorts de retenção analisados
- [ ] Feature adoption mapeada
- [ ] Temas de suporte/bugs priorizados
- [ ] Kill/simplify list publicada
- [ ] 3 bets com métricas e donos
- [ ] Roadmap alinhado ao wedge
- [ ] Review de produto no calendário
