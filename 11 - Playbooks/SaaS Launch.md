# SaaS Launch

## Objetivo

Lançar (ou relançar) um SaaS até ativação e retenção no ICP — com onboarding até o aha, packaging inicial e canal dominante — sem confundir “abriu o app” com product-market fit.

Resolve launches de vanity (Product Hunt sem retenção), feature dumps e GTM desalinhado do produto.

---

## Filosofia

- SaaS não se lança com press release. Se lança com path to aha.
- PMF precoce = retenção no ICP + willingness-to-pay, não MAU inflado.
- Wedge > plataforma. Plataforma nasce de wedge vitorioso.
- PLG sem instrumentação é sorte. Sales sem produto ativável é teatro.
- Time-to-value é a métrica escondida do launch.
- Melhor 50 accounts ativos que 5.000 signups zumbis.
- Preço e limites fazem parte do produto no day 1.
- Launch é uma onda de aprendizado com gates — não um único dia.

## Framework

### 1. Canvas de SaaS Launch (1 página)

1. ICP (empresa + buyer + user)
2. Job-to-be-done e dor mensurável
3. Wedge feature (o job #1)
4. Aha moment (definição explícita)
5. Path to aha (passos máximos)
6. Motion (PLG / sales-assisted / sales-led)
7. Packaging e preço
8. Canal #1
9. Métricas de success/fail (prazo)
10. Dono de produto + dono de GTM

### 2. Sequência

```
ICP + wedge definidos
        ↓
MVP ativável (não “completo”)
        ↓
Onboarding até aha instrumentado
        ↓
Soft launch (design partners / owned)
        ↓
Mensagem + preço alinhados
        ↓
Canal #1 com volume controlado
        ↓
Cohort: ativação, retenção D7/D30, $
        ↓
Iterar uma variável
        ↓
Public launch só com sinal
```

### 3. Defina o aha e instrumente

Aha bom: o usuário/companhia vê o resultado prometido (relatório gerado, lead enriquecido, workflow rodando).

Instrumentação mínima:

| Funil | Evento |
|-------|--------|
| Signup | fonte, ICP tags |
| Setup | integração / first data |
| Aha | evento de valor |
| Habit | uso semanal core |
| Paid | trial→paid / expansion |

Sem aha medido: você está lançando no escuro.

### 4. Packaging de lançamento

```
Free/Trial → prova o aha
        ↓
Starter → time pequeno / um job
        ↓
Growth → colab + limites + integrações
        ↓
Enterprise → governance (só se motion sales)
```

Regra: menos de 3 planos no launch. Complexidade mata conversão.

### 5. Critérios pós-launch (30–60 dias)

- **Dobrar canal**: ativação forte + retenção cohort no ICP + CAC ou pipeline saudável
- **Iterar produto**: tráfego ok, aha fraco
- **Iterar mensagem/pricing**: aha ok, conversão fraca
- **Matar wedge**: sem retenção após iterações honestas

## Aplicações

### SaaS

Feature launch = mini GTM: quem, job, aha, adoption metric, enablement do time.

### IA

Modele custo de inference no pricing. Lance com qualidade esperada e human-in-loop se necessário. “Chat genérico” não é wedge.

### Empresas B2B

Design partner → ROI case → outbound/partners. SSO/security só quando o motion exige — não atrase aha.

### Produtos Digitais

Se freemium: paywall depois do aha, não antes. Se paid: trial com setup guiado.

### Startups

Fundador no suporte e nas calls de churn early. Cada logout/abandono é entrevista.

## Erros Comuns

| Erro | Efeito | Correção |
|------|--------|----------|
| Launch sem aha definido | Signups vazios | Definir + instrumentar |
| Feature igual concorrente | Commodity | Wedge de job |
| Public launch cedo | Ruído | Soft → signal → public |
| Trial infinito | Nunca converte | Prazo + gatilho valor |
| Ignorar time-to-value | Churn silencioso | Onboarding rígido |
| Multi-canal day 1 | Diluição | 1 canal dominante |
