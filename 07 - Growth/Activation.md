# Activation

## Objetivo

Levar o usuário do signup até a primeira vitória real — o aha — rápido o suficiente para retenção e LTV fazerem sentido.

Resolve o buraco entre “entrou” e “nunca mais voltou”.

---

## Filosofia

- Ativação é o crescimento mais barato. Adquirir sem ativar é pagar para ensinar o churn.
- Aha ≠ feature tour. Aha = resultado no job do usuário.
- Time-to-value vence onboarding longo e “completo”.
- Empty state ruim é churn silencioso.
- Setup heroico não escala. Templates e defaults inteligentes sim.
- Segmente ativação por persona/job. Um funil médio mente.
- Ativação fraca disfarçada de “educação” ainda é ativação fraca.
- Meça comportamento, não conclusão de checklist cosmético.

---

## Framework

### 1. Defina o aha com rigor

Pergunte: qual ação + resultado faz o usuário pensar “isso vale a pena manter”?

Escreva em uma linha:

`Usuário X completa ação Y e vê resultado Z em ≤ T tempo`

Se Z for “viu o dashboard”, você ainda não tem aha.

### 2. Mapeie o caminho crítico

```
Signup / login
        ↓
Setup mínimo (só o bloqueante)
        ↓
First value action
        ↓
Aha (resultado visível)
        ↓
Segundo uso agendado (hábito inicia)
```

Liste cada campo, permissão e decisão. Corte o que não é bloqueante.

### 3. Diagnóstico de drop-off

| Degrau | Sintoma típico | Hipótese |
|--------|----------------|----------|
| Pós-signup | Bounce imediato | Expectativa errada / ICP |
| Setup | Abandono no formulário | Fricção / permissões |
| First action | Não clica no core | UI confusa / empty state |
| Aha | Usa sem “wow” | Valor não aparece |
| Return | Não volta em D1/D7 | Sem trigger de hábito |

Ataque o maior buraco primeiro. Não espalhe 10 tutoriais.

### 4. Alavancas na ordem certa

1. **Defaults**: pré-preencher, templates, sample data útil
2. **Escopo**: menos campos, SSO/import depois
3. **Guidance in-product**: checklist amarrada ao aha, não a features
4. **Human assist** (ACV alto): setup call, concierge
5. **Lifecycle**: nudge no momento certo pós-quase-aha

### 5. Instrumentação mínima

- % signup → aha (por cohort/canal)
- Tempo mediano até aha
- Drop por degrau do caminho crítico
- Ativação por persona / plano / dispositivo

Meta: suba a taxa e baixe o tempo. Em paralelo.

### 6. Ritual

- Review semanal do funil de ativação
- 1 experimento por sprint no pior degrau
- Entrevistas com “quase ativou” e “nunca ativou”

## Aplicações

### SaaS

Checklist até primeiro outcome. Templates por caso de uso. Integração crítica como fast-path, não tour genérico.

### IA

Primeiro output de qualidade no job real do usuário. Prompt starter / workflow pronto. Sem “configure API key e boa sorte”.

### Empresas B2B

Time-to-first-value no piloto. Champion ativado antes do rollout. Treino curto > deck de 40 slides.

### Produtos Digitais

Primeira sessão entrega prova. Permissões pedidas no momento de necessidade, não no launch.

### Startups

Conserte ativação antes de dobrar ads. Se aha < 40% do signup qualificado, aquisição é vazamento.

## Erros Comuns

| Erro | Efeito | Correção |
|------|--------|----------|
| Tour de features | Fadiga, zero aha | Caminho ao outcome |
| Setup demais | Abandono | MVP do setup |
| Um funil para todos | Média cega | Segmentar jobs |
| Só email de onboarding | Ignorado | In-product first |
| Aha = “completou perfil” | Falsa métrica | Resultado no job |
| Empurrar pro pago cedo demais | Churn / chargeback | Aha antes de paywall agressivo |

---

## Checklist

- [ ] Aha definido em uma frase (ação + resultado + tempo)
- [ ] Caminho crítico mapeado e instrumentado
- [ ] Maior drop-off identificado e priorizado
- [ ] Templates/defaults cobrem o caso #1 do ICP
- [ ] Time-to-aha medido por cohort
- [ ] Onboarding aponta ao aha, não ao feature dump
- [ ] Ativação no KPI da empresa (não só acquisition)
- [ ] Experimentos semanais/quinzenais no funil
- [ ] Entrevistas com não-ativados existem
- [ ] Canais são julgados por ativação, não só por signup
